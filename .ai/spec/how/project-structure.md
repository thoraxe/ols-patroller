## Key Entry Points

- `uv run patrol.py` → `main()` → argparse → env check → resolve kubectl →
  `ensure_wiki_repo(wiki_path.parent)` (git backing on/off for the process)
  [DONE: #3] → `one()` → `asyncio.run(run_patrol(...))`.
- `--loop` runs the whole process on one event loop: `asyncio.run` over a loop
  coroutine that awaits each patrol (try/except per patrol — an exception is
  logged and the loop continues) and `time.sleep`s the interval between patrols
  (a blocking wait is deliberate: the loop has no concurrent work while idle,
  and a blocking sleep is trivially ctrl-c-interruptible); `KeyboardInterrupt`
  stops cleanly. The console surface is pinned: the catch-and-continue line
  `[patrol] patrol failed (<error>); continuing loop` (stderr) and the stop
  line `[patrol] stopped.`. `--once` (default) keeps its single `asyncio.run`
  and re-raises patrol failures [DONE: #50 — was a fresh `asyncio.run` per
  patrol inside `one()`, which stranded loop-bound engine state on a closed
  loop].
- Container: `ENTRYPOINT ["python3.12", "patrol.py"]` with default
  `CMD ["--loop", "--interval", "21600", "--wiki", "/wiki/cluster-wiki.md"]`;
  dependencies were pip-installed from `requirements.txt` at build — nothing
  resolves or installs at container start [DONE: #1] [DONE: #25].
- `run_patrol()` is the whole patrol lifecycle: load wiki → in-flight AgenticRuns →
  build agent → stream exploration → shape pass → wiki validation (one repair
  pass on failure, carrying the rejected wiki's budget warning when over
  budget) → findings/notify delivery → stale-entry expiry (`expire_stale_entries`,
  passed the on-disk wiki and `STALE_AFTER`) [DONE: #7] → anomaly-log
  compaction (`compact_anomaly_log`, passed `WIKI_ANOMALY_KEEP`)
  [DONE: #40] → frontmatter stamping → the soft-budget warning
  (`wiki_budget_warnings` on the final wiki, stderr — post-stamp, rule 29)
  [DONE: #40] →
  wiki write → commit/push [wiki gate + stamp: DONE: #5].
- `--wiki-stats` branches in `main()` right after argparse, before the env check,
  kubectl resolution, and `ensure_wiki_repo`: read the wiki (die naming the path
  when absent) → one stderr warning when it fails `validate_wiki` →
  `wiki_stats(content)` → `wiki_churn(wiki_history(wiki_path, WIKI_CHURN_WINDOW))`
  → print the block (rule 24) → exit 0 [DONE: #8].

## Naming Conventions

- Single-file layout is intentional (hacky PoC); growth planned is additive
  (tests/, image, manifests) rather than a package split.
- Section banners (`# ----…---- name`) divide the file; keep new code in the
  matching section.
- Env vars are prefixed `PATROL_`; cluster-tool, wiki-git, and wiki-schema
  constants live in the config region. Wiki-git push constants (`PUSH_ATTEMPTS`,
  `PUSH_TIMEOUT`, `PUSH_BACKOFF`) are read at call time so tests can bound retries.
  The working-set budgets (`WIKI_ANOMALY_KEEP`, `WIKI_CHAR_BUDGET`) follow the
  same call-time pattern — passed to the compaction pass by `run_patrol`, read
  inside `wiki_budget_warnings` — so tests can bound them [DONE: #40].
